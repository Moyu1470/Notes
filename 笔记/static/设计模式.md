# 1.单例模式管理器

### 作用：保证类只有一个实例 并提供一个访问该实例的全局节点

#### 解决的问题： 保证类只有一个实例   并   为该实例提供一个全局访问点

![](static/设计模式_images_1.png)

```C#
public sealed class SingletonEager  
{  
    private static readonly SingletonEager _instance = new SingletonEager();  
    public static SingletonEager Instance => _instance;  
    private SingletonEager()
     { 
         /* 防止外部 new */ 
     }  
}
```

# 2.工厂模式

### 核心：在父类中提供一个创建对象的方法，允许子类决定实例化对象的类型
###           将“实例化具体产品”的决策委托给子类（或具体实现）。意图是把创建行为封装，让父类或客户端通过抽象接口来获取产品而不直接 new 具体类型。

#### 经典实现：有抽象创建者 Creator，它定义一个抽象工厂方法 FactoryMethod()，由 ConcreteCreator 创建 ConcreteProduct。客户端通过 Creator 使用产品，但无需关心产品具体类。

```C#
// Product 抽象  
public interface IProduct  //提供的接口  将产品的具体实现交给子类
{  
    void Use();  
}  
  
// 具体产品 Apublic class ConcreteProductA : IProduct  //子类对象A 继承IProduct接口
{  
    public void Use() => Console.WriteLine("Using Product A");   
}  
  
// 具体产品 Bpublic class ConcreteProductB : IProduct  //子类对象B 继承Iproduct接口
{  
    public void Use() => Console.WriteLine("Using Product B");  
}  
  
// Creator 抽象（定义工厂方法）  
public abstract class Creator  //抽象创建者基类
{  
    // 工厂方法，由子类决定创建哪种产品  
    protected abstract IProduct FactoryMethod();  //抽象方法 提供给子类  子类必须重写  返回类型为产品基类
  
    
    public void DoWork()                          // 模板方法：使用创建出的产品   
    {        var product = FactoryMethod();  
        Console.Write("Creator used -> ");  
        product.Use();  
    }}  
  
// 具体 Creator：创建 ProductApublic class ConcreteCreatorA : Creator  //创建者子类A 
{  
    protected override IProduct FactoryMethod() => new ConcreteProductA();  //实现方法重写  创建产品A
}  
  
// 具体 Creator：创建 ProductBpublic class ConcreteCreatorB : Creator  //创建者子类B
{  
    protected override IProduct FactoryMethod() => new ConcreteProductB();  //实现方法重写  创建产品B
}  
  
// 使用  
class Program  
{  
    static void Main()  
    {        Creator c1 = new ConcreteCreatorA();  //实例化创建者子类A 父类装子类 符合里氏替换原则 
        Creator c2 = new ConcreteCreatorB();       //实例化创建者子类B 父类装子类 符合里氏替换原则 
        c1.DoWork(); // Using Product A            //用创建者基类的子类A的实例来调用创建者基类中的DoWork方法
                                                   //DoWork方法会调用由子类负责具体实现的方法 来得到对应产品
                                                   
        c2.DoWork(); // Using Product B            //用创建者基类的子类B的实例来调用创建者基类中的DoWork方法
                                                   //DoWork方法会调用由子类负责具体实现的方法 来得到对应产品
    }   
}
```

#### 变体
```C#
public class DelegatingCreator  
{  
    private readonly Func<IProduct> _factory;  
    public DelegatingCreator(Func<IProduct> factory) => _factory = factory;  
    public void DoWork() => _factory().Use();  
}  
// 注册时： new DelegatingCreator(() => new ConcreteProductA());
```

````ad-tip
Creator 隐藏了创建细节，客户端只通过 Creator 的接口使用产品。

适合需要在多个子类中改变产品创建方式的框架/基类设计场景（例如不同策略下创建不同的策略对象）。
````

# 3.抽象工厂

### 是一种创建型设计模式， 它能创建一系列相关的对象， 而无需指定其具体类。

### 定义一组创建相关对象的方法（例如 CreateButton、CreateCheckbox）。每个具体工厂返回同一风格的产品族。

```C#
// 抽象产品  
public interface IButton { void Paint(); }       //按钮接口基类
public interface ICheckbox { void Paint(); }     //复选框接口基类
  
// Windows 产品  
public class WindowsButton : IButton { public void Paint() => Console.WriteLine("Windows Button"); }         //WINDOWS系统下的 按钮的具体实现
public class WindowsCheckbox : ICheckbox { public void Paint() => Console.WriteLine("Windows Checkbox"); }   //WINDOWS系统下的 复选框的具体实现
  
// Mac 产品  
public class MacButton : IButton { public void Paint() => Console.WriteLine("Mac Button"); }                 //IOS系统下的 按钮的具体实现
public class MacCheckbox : ICheckbox { public void Paint() => Console.WriteLine("Mac Checkbox"); }           //IOS系统下的 复选框的具体实现
  
// 抽象工厂  
public interface IGUIFactory                                                                                 //工厂基类
{  
    IButton CreateButton();                                                                                  //工厂接口基类提供的待子类实现的按钮方法
    ICheckbox CreateCheckbox();                                                                              //工厂接口基类提供的带子类实现的复选框方法
}  
  
// 具体工厂 Windowspublic class WindowsFactory : IGUIFactory                                                  //WINDOWS系统下的工厂方法 继承基类工厂接口
{   
    public IButton CreateButton() => new WindowsButton();                                                    //将基类待实现的方法导向 WINDOWS系统下 对按钮的具体实现 
    public ICheckbox CreateCheckbox() => new WindowsCheckbox();                                              //将基类待实现的方法导向 WINDOWS系统下 对复选框的具体实现 
}  
  
// 具体工厂 Macpublic class MacFactory : IGUIFactory                                                          //IOS系统下的工厂方法 继承基类工厂接口
{  
    public IButton CreateButton() => new MacButton();                                                        //将基类待实现的方法导向 IOS系统下 对按钮的具体实现 
    public ICheckbox CreateCheckbox() => new MacCheckbox();                                                  //将基类待实现的方法导向 IOS系统下 对复选框的具体实现 
}  
  
// 客户端  
public class Application                                                                                      //提供给外部的具体端口
{  
    private readonly IButton _button;                                                                         //用来存储最终需要实现的按钮对象效果
    private readonly ICheckbox _checkbox;                                                                     //用来存储最终需要实现的复选框对象效果
  
    public Application(IGUIFactory factory)                                                                   //交互端口（客户端）构造函数  只需要传入对应的工厂类型 即可创建对应工厂方案的 所有实现
    {        
        _button = factory.CreateButton();  
        _checkbox = factory.CreateCheckbox();  
    }  
    public void Paint()                                                                                       //绘制方法 调用传入进来的具体效果的具体实现
    {        
        _button.Paint();  
        _checkbox.Paint();  
    }
}  
  
// 使用  
class Program2  
{  
    static void Main()  
    {        
             IGUIFactory factory = new WindowsFactory(); // 或 new MacFactory()                                 //用基类工厂类型来装子类工厂 并将其实例化
             var app = new Application(factory);                                                                //之后传给客户端  识别工厂类型 来调用工厂类型内 对应的成套方法
             app.Paint();                                                                                       //调用客户端中的绘制方法
    }
}
```


````ad-tip
抽象工厂将“创建多个相关对象”的职责集中，确保产品之间一致（同一风格）。

客户端只依赖抽象工厂与抽象产品接口，切换工厂即可切换整套组件。
````
